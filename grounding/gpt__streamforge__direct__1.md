Acid design is a high-intensity digital aesthetic built from deliberate visual friction. For Streamforge, it should feel like a live development environment pushed into broadcast mode: technical, unstable in appearance, but precise underneath. The result should be energetic rather than chaotic—an interface made for working developers, not a nostalgic rave poster pasted over a generic SaaS page.

**Palette.** Start with a near-black base—charcoal, ink, or a subtly tinted ultraviolet black—rather than pure black. Use a small set of synthetic accents at full intensity: toxic lime, electric violet, hot magenta, signal cyan, and occasional warning orange. These colors should behave like system states: lime for live activity and successful builds, violet for AI output, cyan for code and interaction, red-orange for errors or destructive actions. Large neutral areas keep the accents legible. Gradients can appear, but they should feel spectral, irradiated, or heat-mapped rather than soft and decorative.

**Typography.** Pair an assertive grotesk or extended display sans with a practical monospace. Headlines can be wide, compressed, oversized, tightly tracked, or set in blunt uppercase to create the feeling of a transmission banner. The monospace carries prompts, model output, repository metadata, viewer counts, timestamps, and labels. Body copy remains clean and readable; acid styling should not compromise comprehension. Typography can occasionally become structural—cropped at edges, repeated, outlined, or used as a background signal—but the core hierarchy must stay obvious.

**Texture.** The surface language comes from screens and computation: scan lines, subtle noise, dithering, terminal grids, pixel artifacts, waveform traces, chromatic offsets, cursor blinks, and faint compression glitches. Use these sparingly and with intent. The page should suggest live data moving through a system, not simulate a broken monitor. Hard borders, one-pixel rules, luminous focus rings, and restrained shadows are more appropriate than soft cards and glossy glassmorphism.

**Layout logic.** Build the composition like a hybrid of an IDE, broadcast control room, and editorial poster. Use a visible grid, modular panes, code-window framing, stacked status bars, and asymmetrical spans. The hero should foreground the product itself: a live split view where prompt, AI response, code diff, build status, and stream chat coexist. Some elements may overlap grid lines or break the container to create pressure and momentum, while primary reading paths remain conventional. Dense technical information should be balanced by large fields of empty dark space.

**Motion and interaction.** Motion should communicate execution: text streaming into a prompt window, code lines changing, build indicators pulsing, branches forking, and viewer presence updating. Transitions should be fast, linear, and mechanical. Avoid slow floating blobs or decorative parallax. The page should feel live even when static, but animation must respect reduced-motion preferences and never interfere with reading code.

**What it borrows from.** The direction draws from early web graphics, cyberpunk interfaces, rave and acid-house flyers, terminal culture, demoscene visuals, industrial signage, Y2K software skins, glitch art, and contemporary experimental editorial design. It also borrows the information density and keyboard-first confidence of developer tools. The useful common thread is not retro nostalgia; it is the sense that software is an active, visible medium.

**What it rejects.** It rejects the polished sameness of conventional B2B SaaS: pastel gradients, floating rounded cards, generic 3D mascots, oversized pill buttons, vague productivity claims, and excessive whitespace with little information. It also rejects performative chaos—illegible type, random distortion, nonstop animation, or neon applied without semantic purpose. Streamforge should look culturally sharp and technically credible. The acid influence supplies energy; the developer-tool foundation supplies trust.
