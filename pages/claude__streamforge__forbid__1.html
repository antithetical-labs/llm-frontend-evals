01 / HOW IT WORKS

Three panes, one timeline.

Every Streamforge broadcast is captured as three synchronized tracks plus a git history. Scrub any of them and the others follow.

1

A developer goes live

Install the CLI, run streamforge go, and your editor, terminal and assistant session are captured and published. Nothing else to configure.

2

You watch the reasoning, not just the result

Prompts on the left, model output in the middle, the live diff on the right. Jump to the moment a test broke, or to the prompt that fixed it.

3

You fork and take over

One click clones the repository at the exact commit on screen, along with the prompt transcript up to that point. Continue in your own assistant.

02 / FEATURES

Built for people who read diffs for a living.

No reaction faces, no cropped webcams over an IDE. Streamforge treats the code as the content.

Prompt transcript

Searchable prompt history

Every prompt and completion is indexed as text alongside the video. Search a stream — or all 26,000 archived streams — for the phrasing that actually produced working code.

  • Full-text search across archives
  • Filter by model, language, framework
  • Copy any prompt with one keystroke
Fork anywhere

Timeline-accurate forks

Streams are backed by a real repository, committed automatically at each accepted change. Fork from the head, from a tagged milestone, or from the second before everything broke.

  • Clone with prompt transcript attached
  • Diff your fork against the streamer's head
  • Open a PR back into the original
Low-latency chat

Review in the moment

Chat is line-aware. Reference auth/mod.rs:42 and it renders as a snippet the streamer can accept as a suggested edit, live, without leaving the session.

  • Inline code suggestions from viewers
  • Sub-second latency to 100k concurrents
  • Secrets scrubbed before broadcast
