§ 01

How it works

STEP 01

Pipe your session

One CLI command wraps your assistant. Streamforge captures prompts, responses, tool calls and file writes — not your screen.

STEP 02

Viewers get three panes

Prompt log, model output, and the live working tree. Scrub back to any turn and read exactly what was asked.

STEP 03

Chat feeds the context

Suggestions from chat can be promoted into the prompt box — with attribution — if the streamer accepts them.

STEP 04

Fork at any timestamp

Every turn is a commit. Fork the repo at minute 12 and take the build somewhere else. Credit stays attached.

§ 02

Three things nothing else does

01Timeline fork

Fork the repo at any second of the stream

Streamforge writes a commit per assistant turn, so the git history is the video timeline. Drag the scrubber, press F, and get a branch that matches the frame on screen.

  • Shallow clone in under two seconds
  • Prompt history preserved in commit trailers
  • Diff view against the streamer's HEAD

03Co-drive

Hand the keyboard to the chat, safely

Co-drive lets a streamer grant a viewer write access to a sandboxed worktree for a fixed number of turns. Their changes land as a pull request, never straight on main.

  • Turn-limited, revocable grants
  • Sandbox: no network, no secrets, no shell
  • Auto-opens a PR with the prompt trail attached
