How it works

Three moving parts, all visible at once.

Streamforge hooks into your editor and your assistant, then publishes the session as a structured stream — not just a screen recording.

01

A developer goes live

Install the CLI, point it at a repo, run forge live. Your prompts, the model's replies, terminal output and file diffs are captured as separate synced tracks.

02

You watch the reasoning, not the mouse

Read the prompt that produced a change, expand the model's full response, scrub back to any commit. Ask questions in chat that are pinned to the exact line being discussed.

03

You fork and take over

One click clones the repo at the current commit, along with the prompt history and context files. Continue from where the streamer is, with your own assistant.

Features

Built for people who read diffs for a living.

Prompt track

Every prompt, timestamped

The prompt log is a first-class artifact. Search it, diff it against another stream, or copy a whole prompt chain into your own project.

  • Full-text search across all public sessions
  • Token counts and model settings shown inline
  • See retries and dead ends, not just the winning attempt
Forkable repos

Fork any stream, any moment

Streams are backed by real git history. Grab the exact tree state at 00:41:12, including the assistant's context window and project rules file.

  • Clone at commit, at chapter, or at latest
  • Licence and attribution attached automatically
  • Push back a fix as a stream-visible pull request
Replay engine

Replays that behave like code

Recordings keep their structure after the stream ends. Step through a build the way you'd step through a debugger — one prompt at a time.

  • Chapter markers auto-cut at each green test run
  • Jump straight to the moment a bug was introduced
  • Speed-independent: text tracks, not video scrubbing
