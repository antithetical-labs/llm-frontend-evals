How it works

Three commands from your terminal to a live audience.

Streamforge hooks into the assistant you already use and the repo you already have. Nothing to rewrite, no separate branch to babysit.

01

Attach the CLI

Run streamforge start in your project. It taps your assistant's request stream and your working tree — Cursor, Copilot, Claude Code, Aider, or a plain API loop.

02

Broadcast three panes

Viewers get the prompt, the token stream, and the live diff side by side — timestamped and synced to the same clock, so cause and effect stay obvious.

03

Viewers fork mid-stream

Every commit is pushed to a public mirror. A single keystroke gives anyone watching the repo at that exact moment, prompt history attached.

What you get

Built for people who read diffs for a living.

Forkable

Fork the exact commit on screen

Not the repo as it ends up — the repo as it is, at the frame you're looking at. Each fork carries the prompts that produced it as commit trailers, so git log tells the whole story.

$ streamforge fork mkosinski/rate-limiter@live cloned → ./rate-limiter (9c41ab2) prompt-log → .streamforge/prompts.jsonl
Searchable

Every prompt is indexed

Full-text search across the prompt log of every public stream. Find how six people phrased the same migration, or jump straight to the moment a regression was introduced.

  • filter: language, model, repo size
  • jump-to-timestamp from any result
  • diff-linked: prompt ↔ commit ↔ test run
Replayable

Replay against a different model

Scrub the timeline, pick any prompt, and re-run it with another model on your own key. Streamforge branches the repo at that point so you can compare outputs side by side instead of arguing about them.

  • deterministic checkout per replay
  • side-by-side diff of two outputs
  • open a PR back to the streamer
