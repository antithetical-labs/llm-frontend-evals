// how it works

Go live in three steps

No overlays, no scene graphs, no production setup. If you can run a terminal, you can broadcast.

Install the CLI

One package captures your editor, your prompts, and your model's responses. Your keystrokes never leave the stream raw; we render the session, not your screen.

Stream your session

Viewers see a structured feed: each prompt, the model's output, and the resulting diff, synced to your actual repo. They can pause and inspect any commit.

Share the repo

Every stream carries a forkable repository. Someone watches you build a rate limiter, forks it, and ships their own version before your stream ends.

// features

Built for people who read diffs for fun

Streaming tools were made for gamers. This one was made for your workflow.

Prompt-level replay

Scrub to any prompt in a past broadcast and see the exact code state at that moment. The transcript and the git history are the same timeline.

$ forge replay mara-builds/api-gateway --at a3f91c2

One-click forks

Every stream exposes its repo. Fork from the latest commit or from any point in the broadcast, with the full prompt history included as structured metadata.

$ forge fork mara-builds/api-gateway

Chat that speaks code

Chat messages can reference lines, files, and commits. Ask "why that index on line 42?" and the streamer sees an anchored thread, not a scrolling wall.

@mara: src/limiter.ts:14 — why sliding window over token bucket?
