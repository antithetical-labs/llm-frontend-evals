How it works

Three steps. No production setup, no OBS scene graph.

Streamforge reads from the tools you already have open. Your editor, your terminal, your assistant — piped into a layout your viewers can read at a glance.

01

Attach the agent

Install the CLI and start your assistant through it. Streamforge captures prompts, tool calls, model responses, diffs, and command exit codes as structured events — not just pixels.

$ npx streamforge attach -- claude
02

Go live in a readable layout

Viewers get four synced panes: prompt, model output, working diff, and terminal. They can scrub back to any prompt without waiting for a VOD to render.

$ streamforge go-live --repo .
03

Viewers fork and follow up

Any viewer can fork the repo at the exact commit on screen, with the full prompt transcript included as commit trailers. They comment on lines, not on a chat river.

$ streamforge fork 431 --at 00:42:07

01 / Transparency

The whole loop, including the parts that failed

Most AI coding content is a highlight reel. Streamforge streams the retries: the prompt that was too vague, the hallucinated import, the three-minute detour through a stale migration. That's the part you can actually learn from.

  • Every prompt and response captured verbatim, token counts included
  • Terminal output with exit codes and timing, not a screenshot
  • Reverted commits stay in the timeline, clearly marked

02 / Forking

Fork any stream's repo at any second

Every stream is backed by a real Git repository. Hit fork and you get the tree exactly as it looked on screen, plus the prompt history attached to each commit — so you can replay the reasoning or branch away from it.

  • Fork at a timestamp, a commit, or the current HEAD
  • Prompt transcripts land as commit trailers you can grep
  • Dev container config included, so make dev just runs
  • Push your fork back as a "reply stream" the author can watch
